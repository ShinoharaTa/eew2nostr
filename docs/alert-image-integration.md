# 発令エリア画像の投稿添付(viewer 画像APIとの統合)

投稿に発令エリアを強調した日本地図の画像URLを添付する。画像そのものは
eew2nostr-viewer 側の画像APIがレンダリングし、bot は URL を組み立てるだけ。

- 画像API本体: eew2nostr-viewer の `/images/alert.webp`
  (viewer の README、viewer#53 / #55 / PR #54 / #56 を参照)
- 色の体系は本リポジトリの #35 / #40 で決めた「色 = 警戒レベル」をそのまま使う

## 役割分担(契約)

| 責務 | 担当 |
| --- | --- |
| 現象 → 色(警戒レベル)の判定 | bot(既存の `style.ts` のロジック) |
| 県コード+色トークン → 地図画像 | viewer 画像API |

**bot 側で色判定を再実装しない。** `severityColor` / `intensityColor` /
`VOLCANO_LEVEL_COLOR` が返す絵文字を、そのままトークンへ写像するだけにする。
色のロジックが2か所に育つと #40 のような不整合が再発するため。

## 画像APIの仕様(2026-09-10 時点)

```
GET https://eew2nostr-viewer.vercel.app/images/alert.webp?pref=13:red&pref=11:yellow
```

| パラメータ | 内容 |
| --- | --- |
| `pref` | `コード` または `コード:色`。コードは JIS X 0401(1〜47、ゼロ埋め不要)。繰り返し・カンマ区切り可。色省略時は `key` の色 |
| `key` | 色省略時の既定色(既定 `red`) |
| `w` / `h` | 100〜2000。既定 1200×630(OGP) |
| `view` | `auto`(既定、発令県と震源が収まる範囲へ自動ズーム)/ `japan`(全国図) |

震源のパラメータ(viewer#60 / PR #61 で追加。第2段の EEW 用):

| パラメータ | 内容 |
| --- | --- |
| `epi` | 震源の `緯度,経度`(例 `32.7545,130.762`)。✕ マークを置く。緯度 20〜50 / 経度 118〜156 |
| `int` | 最大震度。`1`〜`4` / `5-` / `5+` / `6-` / `6+` / `7`。**本リポジトリの `INTENSITY_ORDER` と同じ表記**なので変換不要 |
| `over` | `1` で「震度5弱**以上**」と描く。`forecastMaxInt.to === "over"` のとき用 |
| `mag` | マグニチュード 0〜10。`7.3` / `M7.3` どちらも可。表示は小数1桁に正規化される |

- 同一県の重複指定は後勝ち
- 不正値は 400(無視されない。URL組み立てのバグは投稿前に検知できる)
- `int` / `over` / `mag` は `epi` なしで指定すると 400(ラベルは ✕ に添える形のため)
- 右上に「●(色丸) 県名」の凡例が**指定順**に最大8件、溢れは「他n県」
- 震源ラベルは ✕ の右→左→下→上の順に、画像に収まって凡例と重ならない位置に置かれる
- レスポンスは `cache-control: immutable`。**同一URLは恒久に同一画像**として
  CDN にキャッシュされる(内容を変えたいときは URL を変えるのが前提)

## 絵文字 → 色トークンの写像

| style.ts の絵文字 | トークン | 意味 |
| --- | --- | --- |
| ⚫ | `black` | レベル5相当(特別警報・氾濫発生) |
| 🟣 | `purple` | レベル4相当・震度7 |
| 🔴 | `red` | レベル3相当・震度6弱以上 |
| 🟠 | `orange` | 震度4〜5強・噴火レベル3 |
| 🟡 | `yellow` | レベル2相当・震度1〜3 |
| ⚪ | `white` | レベル1 |

## URL 組み立て仕様

1. **対象**: 投稿グループ(`groupForPosting` の1グループ = 1投稿)に含まれる
   発表中(active)のアラートのうち、都道府県コードを導出できたもの
2. **県コードの導出**: `area.code` が6〜7桁なら先頭2桁が都道府県コード
   (`prefecture.ts` と同じ規則。コードを返すバリアント
   `prefectureCodeFromAreaCode` を追加する)。
   3桁系(震度速報の地域・津波予報区・火山・河川)は第1段では対象外
3. **県ごとの色の集約**: 同じ県に複数のアラートがあるときは最も重い色に丸める。
   重さ: `black > purple > red > orange > yellow > white`
4. **順序 = 凡例の表示順**: 重い色 → 軽い色、同色内は県コード昇順。
   凡例は指定順に出るため、この順序がそのまま投稿の見た目になる
5. **形式**: `pref=<code>:<token>` を県ごとに並べる。`key` / `w` / `h` / `view` は
   省略(既定値に任せる)。47県すべて指定しても URL は 700 文字未満
6. **県が1件も導出できなければ画像なし**(URL を付けない)。解除のみの投稿にも
   付けない(発令エリアの視覚強調が目的のため)
7. base URL は設定値にする(自己ホスト viewer に切り替えられるように)

## 投稿への載せ方

- **Nostr**: content の末尾、ハッシュタグの後・FOOTER の前に URL を1行で置く。
  多くのクライアントは content 中の画像URLをインライン展開する。
  NIP-92 (imeta) の付与は任意の改善として後回しでよい
- **文字数収支**: `formatAlertPosts` のグラフェム上限に URL(約90字)を含めて
  計算する。溢れる場合は地域列挙の省略を優先し、URL は落とさない
- **Bluesky**: URL 文字列だけでは画像展開されない(external embed か blob
  アップロードが必要)。**未対応。Nostr のみに URL を添付している。**
  対応するなら画像を fetch → blob upload して embed する。
  下の「段階」の番号とは独立した話題

## 段階

### 第1段: 気象警報・注意報ほか(6〜7桁コードを持つもの)

対象 hazard: weather / sediment / flood / heavy-rain など、`area.code` が
府県予報区・市町村系のコードで来るもの。既存データだけで実装できる。

### 第2段: EEW — 対応済み (震源のみ)

viewer 側の震源パラメータ(`epi` / `int` / `over` / `mag`)は viewer#60 / PR #61 で
実装・デプロイ済み。bot 側は #75 / PR #81 で対応した。

`core/parser.ts` の `EEWReport` に値が揃っていたため、変換は不要だった:

| 画像APIのパラメータ | EEWReport のフィールド |
| --- | --- |
| `epi` | `` `${latitude},${longitude}` `` |
| `int` | `forecastIntensityValue(forecastFrom, forecast)` |
| `over` | `forecast === "over"` のとき `1` |
| `mag` | `magnitude`(数値として解釈できるときだけ) |

- `magnitude` は `"不明"` や `condition` の文字列が入りうる。数値でなければ `mag` を落とす。
  **空文字を `Number()` に渡すと `0` になる**ため、先に空でないことを確かめる
- 予想震度が `UNKNOWN_INTENSITY`(`"不明"`)なら `int` / `over` を落とす。
  ✕ と `M` だけの画像になる
- `int` は `5-` / `5+` の形のまま渡す。`intensityLabel` で漢字に変換して**から**渡す
  必要はない(viewer 側が「震度5弱」と描く)。`+` はクエリ文字列では空白として
  解釈されるため `encodeURIComponent` を通す。viewer 側にも救済があるが依存しない
- 緯度 20〜50 / 経度 118〜156 / マグニチュード 0〜10 の外は画像APIが 400 を返すため、
  URL を組み立てる前に弾いて画像なしに倒す
- **最終報は `finalized`** になる(`eewAlert` の `isLast`)。`active` だけに絞ると
  最も情報が揃った報に画像が付かないため、両方を対象にする

第1段の「県が1件も導出できなければ画像なし」というルールは、EEW については
**震源があれば画像を出す**に緩めてある。

#### 県の塗り(旧 2-b)は行わない

**EEW は発生地(震央地名と震源の ✕)が分かれば十分、という判断のため取り下げた
(#82)。** 対象都道府県を電文から抽出して `pref` を重ねる計画は無い。

再検討する場合に備えて、調査結果は #82 のクローズコメントに残してある。要点:

- 対象地域は電文に入っている。`body.intensity.regions[]`(コード表24・細分区域・
  地域ごとの予想震度を持つ・全種別)と `body.prefectures[]`(コード表22・府県予報区・
  震度を持たない・**VXSE43 / VXSE45 のみ**)の2系統
- 画像APIが要求する JIS X 0401 の県コードとは別体系のため、対応表が別途要る。
  `prefectureCodeFromAreaCode` の「先頭2桁」規則は EEW のコードには使えない
- `sampleData/` の電文は6通すべて予報・震度3で `regions` が空配列。
  実際のコード値は未観測

### 第3段(任意): 震度速報・津波

3桁コード系(震度速報の地域コード、津波予報区)は先頭2桁規則が使えないため、
コード → 都道府県の対応表が別途必要。必要になったら起票する。

## テスト観点

- 同一県に警報+注意報 → 重い色(red)1件に丸まる
- 色の順序: black の県が purple より先に来る
- 6桁コード(府県予報区)と7桁コード(市町村系)の両方から県が引ける
- 3桁コード(震度速報の地域・津波予報区・火山・河川)は無視される。
  県も震源も無ければ URL が付かない(EEW の code 空は震源で拾うので別扱い)
- グラフェム上限ぎりぎりの投稿で URL が欠落しない
- 生成した URL が画像APIの 400 にならない(結合テストで実URLの形式検証)

EEW(第2段・対応済み):

- `magnitude` が `"不明"` / condition 文字列のとき `mag` が付かない
- 予想震度が `"不明"` のとき `int` / `over` が付かず、`epi` だけになる
- `forecast === "over"` のとき `int=<from>&over=1` になる(`int` に `over` が入らない)
- `int` が `5-` / `5+` の生の形で渡る(`intensityLabel` を通していない)
- `pref` が0件でも `epi` があれば URL が付く
- `int=5+` が `%2B` にエンコードされる(生の `+` は空白として解釈されるため)
- `magnitude` が空文字のとき `mag=0` にならない
- 緯度経度・マグニチュードが範囲外なら URL を付けない
- 最終報(`finalized`)にも画像が付き、取消報には付かない
